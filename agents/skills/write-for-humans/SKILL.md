# Write for humans

Lead with the answer, result, or action. Give the reader enough evidence to assess
it; omit introductory praise and recaps of the request. Match detail to the task.
Chat replies rarely need the structure of documentation.

## Wording

- Use plain words, active voice, and a named actor. Address the reader as “you.”
- Keep sentences focused on one idea. Put conditions before instructions.
- Use consistent terms for the same concept. Explain unfamiliar jargon; avoid
  idioms that make reading harder for non-native English speakers.
- State facts precisely. Replace “robust” with the failure it handles, “fast” with
  a measurement, and vague attribution with a named source. Use one hedge only
  where uncertainty matters.
- Cut filler: “great question,” “it's worth noting,” “delve,” “leverage,” and
  “seamless.” Never call the work easy, simple, or obvious.
- Avoid “it's not X, it's Y” framing, performative enthusiasm, and decorative
  analogies. State the useful point directly.
- Keep documentation timeless. Past tense is appropriate when reporting work
  you completed; avoid “currently” and “new” in enduring descriptions.

## Structure and formatting

Use paragraphs for connected reasoning. Use lists for parallel items or steps,
and tables for comparisons. Don't split a sentence into bullets or force three
items where fewer suffice. Use sentence case for headings.

Use code font for commands, paths, flags, and identifiers; bold for UI labels.
Avoid bolding every lead-in. Use descriptive links and unambiguous dates.

Don't add a concluding summary when the reader can see the whole answer. Don't
end with a reflexive offer to continue. Ask questions only when an answer matters.

## Before sending

Delete any opening that carries no information and any ending that repeats the
body. Cut unnecessary hedges, repeated examples, and formatting. Check that claims
have support and the reader can understand each sentence on the first read.

For terminology choices, consult [references/word-list.md](references/word-list.md)
as needed. The [Google style guide](https://developers.google.com/style) provides
the broader reference; do not load it for routine replies.
