# Slide design

Follow the user's brand or template. For a new deck, choose a content-led palette,
clear type hierarchy, and consistent spacing. Vary layouts when the content calls
for it; don't force a visual motif, an icon, or an image onto every slide.

Use charts for quantitative comparisons, diagrams for relationships, and images
when they explain the subject. Text-only slides can work for a focused statement.
Keep labels and citations readable, preserve contrast, and leave room around
content. Avoid decorative accent stripes, generic card grids, and arbitrary
numbering that communicate no structure.

Keep charts editable when PowerPoint supports them. Align text boxes deliberately;
internal padding can move text away from the edge of a neighboring shape. Split
crowded content or enlarge its containers before shrinking text into unreadability.

## Fonts and rendering

The user's PowerPoint and the local renderer may use different fonts. Check what
is installed in the rendering environment. Substitution can change line wrapping,
so apparent fit in a preview is not proof of fit on the destination machine.

Prefer fonts available to both environments. When the user requires a font the
previewer lacks, use it as requested, allow extra space, and disclose the limit
of the preview. Do not assume a fixed list of fonts is installed everywhere.

## Review

Inspect rendered slides at a readable size. Check text overflow, alignment,
contrast, footer collisions, missing template elements, and inconsistent spacing.
Use [quality.md](quality.md) for rendering and file validation.
